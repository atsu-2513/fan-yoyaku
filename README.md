# hair salon FAN 予約システム

LINE Messaging APIと連携した、指名制（スタッフごとの空き時間管理）の予約システムです。

## 予約の流れ（お客様）

1. お客様がLINE公式アカウントに「予約」と送信
2. Botが予約フォームのURL（有効期限30分）を返信
3. お客様がURLを開き、①担当スタッフを指名 → ②メニュー（指名したスタッフが提供しているメニューのみ、価格・施術時間つきで表示。メニューに迷ったら「迷ったら質問に答えて探す」から質問に答えておすすめを見ることもできる） → ③カレンダーでそのスタッフの空き日時（選んだメニューの施術時間ぶん連続で空いている時刻だけが表示される。カレンダー上には、その月のうち空きがある日に○印が表示される） → ④氏名・電話番号・ご相談（任意）を入力して送信
4. 送信と同時にLINEへ「仮予約を受け付けました」と通知。あわせて担当スタッフとオーナーへメールでも通知される（メール通知の設定は下記「メール通知」参照）
5. 担当スタッフ（またはオーナー）が管理画面で予約一覧を確認し「確定する」を押すと、お客様に「予約が確定しました」とLINE通知（お客様がご相談欄に記入していた場合、スタッフが確定時に書いた返信もあわせてお客様に届く）
6. 前日の18:00頃、確定済みの予約にLINEでリマインド通知が届く（詳細は下記「前日リマインド通知」参照）

## 予約のキャンセル

- お客様側: LINEで「キャンセル」と送信すると、そのお客様の今日以降の予約が一覧（ボタン）で表示され、選ぶとその場でキャンセルされる。キャンセル完了もLINEで通知される。
- スタッフ/オーナー側: スタッフ画面・管理画面それぞれの予約一覧から「キャンセル」ボタンでキャンセルできる（電話等でお客様から連絡を受けた場合を想定）。この場合お客様には「キャンセルとなりました」とLINE通知が届く。
- キャンセルされた予約は空き時間の集計から除外されるため、同じ日時が再び予約可能になる。

## キャンセル待ち・空き通知（行きたい日がすでに埋まっているお客様向け）

予約フォームのカレンダー画面に「行きたい日が埋まっていた方はこちら【キャンセル待ち】」ボタンがあります。
お客様はこれを押すと、通常の予約(その場で日時を確定)の代わりに、すでに満席の日時も含めてご希望の日時を
最大3つ（第1〜第3希望）まで選んで送信できます（実際に空いているかどうかはこの時点ではチェックしません。
「行きたい日が埋まっている」ことが前提の機能のためです）。送信すると仮の予約は作られず、「キャンセル待ち」
としてLINE・メールで通知が届きます。

- スタッフ/オーナーは、スタッフ画面・管理画面の「候補日リクエスト（キャンセル待ち）」から内容を確認し、
  都合の良い候補日を1つ選んで「確定する」を押すと、その日時で通常の予約と同じように確定し、お客様にLINE
  通知が届きます（確定直前に、選んだ時間が他の予約で埋まっていないか自動で再確認されるため、まだ空いている
  候補日を誤って二重に確定してしまうことはありません）。どの候補日も難しい場合は「見送る」を押すと、お客様
  にその旨がLINEで通知されます。
- 確定済みの予約がキャンセルされた際、その空いた日時が「別のお客様の第一希望（キャンセル待ちの第1希望）」と
  一致する場合、スタッフ画面・管理画面の「空き通知」にお知らせが表示されます。ここから、その空いた日時への
  変更を促すメッセージ（自由に編集可能。空欄なら定型文）をワンクリックでLINE送信できます。対応しない場合は
  「非表示にする」で消せます。
- 予約一覧の「日時を変更する」ボタンから、確定済みの予約の日付・時間を画面上でそのまま変更できます
  （キャンセル＋再予約は不要）。変更後の日時はその場で空き状況を確認したうえで反映され、お客様には「ご予約
  の日時を変更いたしました」とLINE通知が届きます。空き通知をきっかけにお客様から変更の返事をもらった場合
  などに、この機能で日時だけ差し替えるのに使えます。

## スタッフの空き時間管理

スタッフごとに `/staff/login.html` からログインし、自分の空き時間を自分で「開放」します。
お客様の予約フォームには、指名したスタッフが開放した時間だけが表示されます
（オーナー側で一律の営業時間を設定する方式ではなく、各スタッフが個別に予約を受け付けたい時間だけを開放する方式です）。

- スタッフ用ログイン画面: `<BASE_URL>/staff/login.html`
- スタッフ用ダッシュボード: `<BASE_URL>/staff/`（空き時間の設定・自分の予約一覧・顧客管理・パスワード変更）

### 顧客管理(スタッフごとの簡易リスト)

スタッフダッシュボードの「顧客管理」で、自分が担当したお客様の一覧（お名前・電話番号・予約回数・最終予約日・メモ）を確認できます。
お客様がフォームから予約すると自動で一覧に追加され、電話予約など予約フォームを通さないお客様は「追加する」から手動で登録できます
（電話番号がすでにある場合は、お名前だけ最新のものに更新されます）。メモ欄にはアレルギーやご要望などを自由に書き込め、
予約が入っても上書きされません。この一覧は他のスタッフからは見えず、担当スタッフ本人だけが編集できます。
オーナーは管理画面の「顧客管理（全スタッフ）」から、全スタッフぶんの一覧を横断して閲覧できます
（閲覧のみで、編集・追加・削除は各スタッフの画面から行います）。
各お客様の「履歴を見る」から、そのお客様のこれまでの来店日時・メニュー・状態（仮予約/確定）の一覧を確認できます
（スタッフ画面・オーナー管理画面の両方にあります）。

### 同じ空き時間を複数の日にまとめて設定したい場合

ある日の空き時間を設定したあと、「この日の設定を他の日にコピー」ボタンを押すと、カレンダーが複数選択モードになる。
コピーしたい日をカレンダーから好きなだけタップして選び（連続していない日付でもOK）、
「選択した日にコピーする」を押すと、選んだすべての日にその日の空き時間がまとめて反映される
（定休日を選んだ場合はその日だけ自動的にスキップされる）。自動で繰り返されるわけではなく、
スタッフが必要なタイミングで都度おこなう方式。

定休日と、開放できる候補時間の枠（何時から何時まで）は、管理画面の
「定休日・営業時間」からオーナーがいつでも変更できます（詳しくは下記「オーナー用の管理画面」参照）。
スタッフはここで設定した候補時間の中からしか開放できません。

### 予約の時間単位・メニューごとの施術時間

空き時間の開放・お客様への表示は30分刻みです。メニューには「施術時間」を設定でき
（例: カット60分、カラー90分、パーマ120分）、お客様の予約フォームには、選んだメニューの
施術時間ぶん連続して空いている開始時刻だけが表示されます（例: 90分のメニューを選んだ場合、
30分・60分しか空いていない時間帯は候補に出ません）。施術時間は管理画面の「メニュー管理」から
メニューごとに設定できます（詳しくは下記「オーナー用の管理画面」参照）。

30分刻みへの変更に伴い、これまで1時間単位で開放していたスタッフの空き時間は、初回デプロイ時に
自動的に前後30分ぶん補完されます（例: 「10:00を開放」だけだった場合、自動的に「10:30」も開放済みに
なります）。これは一度だけ行われる移行処理で、今後スタッフが新しく空き時間を開放する際は
30分単位（例: 10:00と10:30は別々に開放が必要）になります。

### スタッフアカウントの作成

初回セットアップ時、以下のコマンドでスタッフアカウントを作成します。

```bash
npm run create-staff
```

`scripts/create-staff.js` 内の `STAFF` 配列を編集すれば、人数や名前・IDを変更できます。
実行すると初期パスワードがターミナルに表示されるので、各スタッフに伝えてください。
スタッフは初回ログイン後、ダッシュボード内の「パスワード変更」から自分で変更できます。
（同じユーザー名がすでに存在する場合はスキップされるので、何度実行しても安全です）

## オーナー用の管理画面

- `<BASE_URL>/admin/`（Basic認証で保護）
- 全スタッフの予約を一覧表示し、どのスタッフの予約でも確定・キャンセル操作ができます。お客様が「ご相談」欄に記入していた場合はここに表示され、確定前にテキスト欄へ返信を書いてから「確定する」を押すと、その返信も一緒にLINEでお客様に届きます。
- 画面下部の「スタッフの空き状況」で、スタッフとお日にちを選ぶと、そのスタッフが開放している時間・予約済みの時間・未開放の時間を確認できます（オーナー側からスタッフの空き時間を変更することはできません。設定自体は各スタッフが自分の画面で行います）。
- 「定休日・営業時間」で、定休日にする曜日と、開店・閉店時刻をいつでも変更できます。保存するとお客様の予約フォーム・スタッフ画面すべてに即座に反映されます。
- 「メニュー管理（共通）」で、全スタッフ共通のメニュー・価格・施術時間（分）を追加・変更・非公開にできます（施術時間は30分単位で扱われ、例えば45分と入力すると60分になります）。
- 「メニュー診断クイズ」で、お客様がメニューに迷ったときの質問と選択肢を自由に追加・編集・削除できます。選択肢ごとに「どのメニューのおすすめにつながるか」を選べます。お客様は複数の質問に答えると、一番多く選ばれたメニューがおすすめとして表示されます（質問数・選択肢数に制限はなく、いつでも増減できます）。質問を1つも登録していない間は、お客様の画面にクイズのボタン自体が表示されません。
- 「スタッフごとのメニュー調整」で、共通メニューのうち特定のスタッフだけ「提供しない」「価格を変える」を設定できます（何も調整しなければ、そのスタッフには共通メニューがそのままの価格で表示されます）。
- 「スタッフの通知先メールアドレス」で、各スタッフの予約通知先メールアドレスを設定できます（下記「メール通知」参照）。
- 「顧客管理（全スタッフ）」で、各スタッフが登録したお客様情報（お名前・電話番号・予約回数・最終予約日・メモ）を横断して閲覧できます（閲覧のみ）。

## 前日リマインド通知

確定済みの予約について、来店日の前日18:00頃にLINEでリマインドを送る機能です。
Renderの無料プランはアクセスが一定時間なければサーバーが休止するため、アプリ内部のタイマーだけでは
決まった時刻に処理を実行できません。そのため、外部の無料スケジューラ（[cron-job.org](https://cron-job.org/)など）から
1日1回、以下のURLにアクセスしてもらうことで実行します。

```
https://<公開URL>/api/cron/send-reminders?key=<CRON_SECRETの値>
```

`key` が環境変数 `CRON_SECRET` の値と一致しないと動作しません（いたずら防止のための合言葉）。
`.env` / Renderの環境変数に `CRON_SECRET` を設定したうえで、外部スケジューラ側に上記URL（`key`に実際の値を入れたもの）を
毎日18:00（日本時間）に呼び出すよう登録してください。

動作確認したいときは、末尾に `&date=YYYY-MM-DD` を付けて開くと、その日付を対象にテストできます
（例: `...&key=...&date=2026-09-10`）。付けなければ常に「明日」が対象になります。

## メール通知

新しい予約が入るたびに、担当スタッフとオーナーへメールでも通知します（LINE通知とは別に、両方届きます）。
無料で使え、独自ドメインを持っていなくても使える [Brevo](https://www.brevo.com/) というサービスを利用しています。

### 設定手順

1. [Brevo](https://www.brevo.com/) で無料アカウントを作成する
2. 管理画面の「Senders, Domains & Dedicated IPs」（送信者・ドメイン管理）から、送信元にしたいメールアドレス
   （オーナーが普段使っているGmail等でOK）を「Add a sender」で登録する
3. そのメールアドレスに届く6桁の確認コードを入力して認証する（このステップだけでよく、独自ドメインの取得・DNS設定は不要）
4. 「SMTP & API」→「API Keys」から新しいAPIキーを発行する
5. Renderの環境変数に以下を設定する

```
BREVO_API_KEY=（4で発行したAPIキー）
MAIL_FROM_ADDRESS=（3で認証した送信元メールアドレス）
MAIL_FROM_NAME=hair salon FAN
OWNER_EMAIL=（オーナー自身が通知を受け取りたいメールアドレス）
```

6. 管理画面の「スタッフの通知先メールアドレス」から、各スタッフの通知先メールアドレスを設定する
   （未設定のスタッフには通知メールは届きません。LINE通知や予約自体には影響ありません）

`BREVO_API_KEY` または `MAIL_FROM_ADDRESS` が未設定の場合、メール送信は自動的にスキップされます
（LINE通知は影響を受けず、これまで通り届きます）。

## セットアップ

### 1. 依存パッケージのインストール

```bash
npm install
```

### 2. LINE Developersでの設定

1. [LINE Developers Console](https://developers.line.biz/) でMessaging APIチャネルを作成
2. チャネルアクセストークン（長期）とチャネルシークレットを取得
3. Webhook URLを `https://<公開URL>/webhook` に設定し、Webhookを有効化
4. **応答メッセージ・あいさつメッセージは必ずOFFにする**（[LINE Official Account Manager](https://manager.line.biz/) の「応答設定」から。ONのままだと、Bot側の予約案内メッセージと一緒にLINE標準の自動応答文が二重に届いてしまいます）

### 3. 環境変数の設定

```bash
cp .env.example .env
```

`.env` を編集して、`LINE_CHANNEL_ACCESS_TOKEN` / `LINE_CHANNEL_SECRET` / `BASE_URL` /
`ADMIN_USER` / `ADMIN_PASS` / `SESSION_SECRET`（ランダムな文字列に変更）を設定してください。

ローカルで動作確認する場合は `ngrok http 3000` などでトンネルを作り、その公開URLを
`BASE_URL` とLINEのWebhook URLの両方に設定してください。
DBはローカルでは `TURSO_DATABASE_URL` 未設定時に自動で `data/fan-yoyaku.db`（SQLite互換のファイルDB）が使われます。

### 4. スタッフアカウントの作成

```bash
npm run create-staff
```

### 5. 起動

```bash
npm start
```

- 予約ページ: `<BASE_URL>/booking/?token=...`（LINEからのリンク経由でのみ有効）
- 管理画面(オーナー用): `<BASE_URL>/admin/`
- スタッフ用ログイン: `<BASE_URL>/staff/login.html`

## データ

予約データは [Turso](https://turso.tech/)（libSQL / SQLite互換のマネージドDB）に保存されます。
Render/Vercelなどファイルシステムが永続化されない環境では、本番で必ず
`TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN` を設定してください。ローカル開発では
これらを未設定にすると `data/fan-yoyaku.db` にファイルとして保存されます。

起動時に、既存の `reservations` テーブルへ `staff_id` 列を自動追加するマイグレーションが
走ります（すでに列がある場合は何もしません）。

## デプロイ（Render / Vercel共通の注意点）

`src/server.js` の `app.listen()` を検出させ、Node.jsサーバーとしてそのまま起動させてください。
（Vercel FunctionsのようなヘルパーでラップするとLINEのWebhook署名検証に必要な生のリクエストボディが
消費されてしまい、`SignatureValidationFailed` で失敗します。）

デプロイ後、LINE DevelopersのWebhook URLを `https://<デプロイ先のURL>/webhook` に更新してください。

## 技術構成

- Node.js / Express（生のリクエストボディをLINEの署名検証に渡せるよう、ヘルパー付きの
  サーバーレスFunctionsは使わない構成）
- `@line/bot-sdk`（Messaging API連携・Webhook署名検証）
- `@libsql/client`（Turso / libSQL、予約・予約用トークン・スタッフ・空き時間の保存）
- スタッフ用ログインは追加パッケージなし（Node標準の `crypto` によるパスワードハッシュ化と
  署名付きセッションCookie）で実装
- 予約ページ・管理画面・スタッフ画面はビルド不要のシンプルなHTML/CSS/JS
